# ADR-0016: Dev-only крейт `slam-testkit` и счётчик аллокаций

- Статус: Принято
- Дата: 2026-10-08

## Контекст
Принцип «ноль аллокаций в горячих путях» (ARCHITECTURE §2, §18) должен проверяться тестами в нескольких крейтах: `slam-engine` (лимитер, update-тик), `slam-render` (отрисовка кадра), `slam-audio` (аудиоколбэк), `slam-osu`. Первый тест лимитера содержал собственный глобальный аллокатор; копировать его в каждый крейт нельзя. Крейта для общей тестовой инфраструктуры в §3 нет.

## Решение
- Новый крейт `crates/slam-testkit`: только тестовая инфраструктура, подключается исключительно через `[dev-dependencies]` и поэтому не попадает в релизную сборку. Сам ни от каких крейтов SLAM не зависит.
- Счётчик аллокаций: `CountingAlloc` поверх `System`, счётчики `alloc`/`realloc`/`dealloc` — в `thread_local` (подсчёт по потоку, параллельные тесты не мешают друг другу).
- Тестовый бинарь устанавливает аллокатор макросом `install_counting_allocator!()`; проверка — `assert_no_alloc(|| ...)`. Освобождения тоже считаются нарушением (`free` может брать блокировку). Если аллокатор не установлен, проверка падает, а не проходит молча.

## Последствия
- Любой горячий путь покрывается тестом в две строки.
- Подсчёт работает только в потоке, вызвавшем `assert_no_alloc`; горячие пути других потоков проверяются вызовом изнутри этого потока.
- Считается только глобальный аллокатор Rust. Память, которую выделяет C-код за FFI (драйверы аудио и GPU, системные библиотеки), прямые вызовы `System` и `mmap` не видны: зелёный тест не гарантирует отсутствие аллокаций в нативных бэкендах `slam-audio` и `slam-render`.
- Требуется нативный TLS у цели (Linux, Windows MSVC, macOS). На целях с TLS через ключи ОС (например, `x86_64-pc-windows-gnu`) первое обращение к счётчику само аллоцирует и рекурсивно входит в аллокатор — тесты с ним там не запускаются.
- Тестовый бинарь с `install_counting_allocator!()` целиком работает на счётном аллокаторе — такие тесты лучше держать в отдельных файлах `tests/*_no_alloc.rs`.

## Отвергнутые варианты
- Крейт `assert_no_alloc` с crates.io: работает через флаг и `abort`/лог, нет счёта по видам операций и проверки установки аллокатора; зависимость ради ~100 строк.
- Модуль `#[cfg(test)]` в `slam-engine`: недоступен другим крейтам.
- Глобальные (не потоковые) атомарные счётчики: ложные срабатывания при параллельных тестах.

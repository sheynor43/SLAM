# ADR-0053: Счётчик FPS для игрока, как в лазере

- Статус: Принято
- Дата: 2026-10-17
- Дополняет [ADR-0021](0021-frame-overlay-and-tracy.md) и [ADR-0015](0015-hud.md) (не заменяет)

## Контекст
Игроку нужен счётчик FPS и времени кадра, как `FPSCounter` в лазере: две строки в правом нижнем углу — время кадра update-потока (`ms`) и FPS отрисовки (`fps`), со сглаживанием, мгновенным показом скачков, цветом по отношению к целевой частоте и затуханием при стабильной работе. Оверлей фреймтайма из ADR-0021 — инструмент разработчика: растровый шрифт, нелокализованные подписи, перцентили. Для игрока он не подходит. В лазере счётчик считает update-поток по часам всех потоков. У нас draw не вызывает update, а update не знает о кадрах draw.

## Решение
- **Отдельный элемент для игрока, а не оверлей ADR-0021.** Логика — порт `FPSCounter` лазера (`slam-play/src/fps_counter.rs`): сглаживание `DampContinuously` с полупериодом 100 мс, скачки дольше 20 мс без сглаживания, FPS окном 250 мс с округлением вверх, текст не чаще раза в 10 мс, цвет красный → оранжевый → салатовый, затухание до 0,7 через 2 с без значимых изменений.
- **Счётчик живёт в потоке draw.** Время кадра draw — интервал между пробуждениями лимитера (`FrameWait::woke_ns`). Время кадра update публикуется движком в `EngineCounters`: интервал между тиками по расписанию (тики, разбуженные вводом раньше срока, не учитываются — иначе время кадра прыгало бы от частоты ввода). Update поднимает атомик до наибольшего интервала (`fetch_max`), draw забирает его раз в кадр (`swap(0)`): при отрисовке реже update ни один скачок не теряется. Если тиков по расписанию между кадрами не было, счётчик берёт прошлое значение. После смены частоты update интервал отсчитывается заново, чтобы интервал между двумя частотами не выглядел скачком.
- **Целевые частоты** — частоты update и draw из настроек. При отрисовке без лимита целью draw считается частота update.
- Сглаживание идёт по шагу потока draw, а не update, как в лазере. На показанные числа это почти не влияет: при 1000 Гц оба шага около 1 мс.
- Отображение — текст MSDF (`slam-text`) с подложкой, буферы фиксированного размера, в кадре без аллокаций. Единицы `fps` и `ms` — ключи Fluent, собираются при подготовке экрана вместе с подписями HUD (ADR-0045). Числа форматируются без Fluent, разделитель тысяч — запятая.
- Настройка `frame.show_fps`, по умолчанию выключена, как `ShowFpsDisplay`. Пока счётчик есть только на экране игры.

## Последствия
- Счётчик дешёвый: одно атомарное чтение и несколько арифметических операций за кадр.
- Счётчик в меню и выбор его положения — отдельная задача. Счётчик тогда переедет из сцены игры на уровень оболочки.
- Нет подсказки по потокам при наведении, клавиши переключения и разделителя тысяч по языку.
- Время кадра update показывает интервал между тиками, а не длительность работы тика: как и в лазере, это частота, а не нагрузка.

## Отвергнутые варианты
- **Подключить оверлей ADR-0021.** Растровый шрифт и нелокализованные подписи, другое содержание. Он остаётся инструментом разработчика.
- **Считать счётчик в update и передавать текст через снапшот.** Update не знает времени кадров draw. Пришлось бы гонять их обратно через атомики, а текст — через тройной буфер каждый тик.
- **Учитывать все тики update, включая тики по вводу.** При быстром вводе время кадра падало бы до долей миллисекунды и не отражало бы частоту update.

# ADR-0002: Модель потоков, ввод по событиям, лимитер

- Статус: Принято
- Дата: 2026-10-08

## Контекст
Нужна минимальная задержка ввода и частоты кадров/update до 8000. Частоту опроса мыши задаёт железо; клиент может только не терять события и обрабатывать их без задержки.

## Решение
- Потоки: Input, Update, Draw, Audio, пул Workers, Scripts, IO (см. ARCHITECTURE §4).
- Input-поток ждёт события ОС (без опроса), ставит наносекундный таймстемп, передаёт через SPSC-кольцо.
- Update просыпается по событию ввода и с заданной частотой; попадания судятся по таймстемпу события.
- Update → Draw через тройной буфер; отрисовка никогда не ждёт.
- Лимитер: абсолютные дедлайны, высокоточный сон + spin последних ~200 мкс.
- Свой дизайн, не копия лазера.

## Последствия
- Точность судейства не зависит от FPS.
- Настройка «частота до 8000» ограничивает update-цикл, а не задержку ввода.
- Нужна дисциплина: ноль аллокаций и блокировок в горячих путях.

## Отвергнутые варианты
- Опрос ввода с фиксированной частотой: добавляет до одного периода задержки.
- Один поток на всё: отрисовка блокирует судейство.

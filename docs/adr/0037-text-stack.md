# ADR-0037: Текстовый стек: встроенные шрифты, harfrust и skrifa, своя раскладка, MSDF через fdsm

- Статус: Заменён ADR-0062 (в части генератора MSDF `fdsm`)
- Дата: 2026-10-13

## Контекст
Интерфейсу (#83, #109) нужен текст: встроенные шрифты с латиницей и кириллицей, пользовательские TTF/OTF, шейпинг, раскладка с выравниванием и переносом, затем MSDF-атлас глифов. ARCHITECTURE §12 называет кандидатов в шрифты (Nunito Sans / Outfit / Manrope, Exo 2) и `cosmic-text`/`rustybuzz` для шейпинга, но выбор не зафиксирован. `rustybuzz` и `ttf-parser` в 2026 году объявлены авторами заброшенными (RUSTSEC-2026-0206, RUSTSEC-2026-0192); преемники — `harfrust` (проект HarfBuzz) и `skrifa` (fontations, Google Fonts).

Ограничения: лицензии без GPL; глифы потом рисуются из MSDF по контурам, растеризатор не нужен; счётчики HUD меняют текст часто, поэтому раскладка должна переиспользовать буферы; `slam-text` зависит только от `slam-render`.

## Решение
- **Встроенные шрифты** — вариативные TTF из `google/fonts`, без изменений, в `assets/fonts/`, лицензия SIL OFL 1.1 (текст лицензии рядом, запись в `THIRD_PARTY_NOTICES`). Встраиваются в бинарник (`include_bytes!`), чтобы текст был доступен до загрузки чего-либо с диска.
  - **Nunito Sans** — текст интерфейса (оси `wght` 200–1000, `wdth`, `opsz`, `YTLC`; используем только `wght`).
  - **Exo 2** — заголовки (ось `wght` 100–900).
  - Outfit отпал: в нём нет кириллицы.
- **Разбор и шейпинг** — `skrifa` (метаданные, cmap, метрики, контуры; MIT/Apache-2.0) и `harfrust` (MIT), оба поверх одного `read-fonts`. Реестр держит по `harfrust::Font` на начертание (байты не копируются); экземпляр с осью `wght` и планы шейпинга по (начертание, вес, письменность) кешируются в контексте раскладки. Метрики строки берутся у экземпляра с вариацией (с учётом `MVAR`). Шрифты и коллекции принимаются байтами; семейство берётся из таблицы `name` (типографское семейство, иначе обычное). Вес задаётся осью `wght` вариативного шрифта, у набора статических начертаний — ближайшим по весу начертанием (по правилам CSS).
- **Реестр** — семейства по имени, `FontId` на начертание, глобальная цепочка фолбэка семейств (в раскладке учитываются первые 8 начертаний вместе с основным). Шрифт для текста выбирается по графемам: первый в цепочке «основное семейство → фолбэки», в котором есть глифы всех символов графемы; иначе основное (`.notdef`). Пробелы и управляющие символы остаются в текущем прогоне.
- **Раскладка своя**, в `slam-text`:
  - абзацы по обязательным разрывам UAX #14, перенос по разрешённым разрывам (`unicode-linebreak`, Apache-2.0);
  - абзац шейпится один раз, потом раскладывается по строкам;
  - слово шире строки рвётся по границам кластеров шейпера;
  - висящие пробелы в ширину и выравнивание не входят;
  - выравнивание влево, по центру, вправо;
  - метрики строки берутся у основного шрифта при заданном весе.
  - Результат — глифы `(FontId, вес, glyph id, x, y базовой линии)` в пикселях и границы строк; от GPU не зависит.
- **Без аллокаций на прогретых буферах.** Раскладка пишет в переиспользуемый `Layout` через контекст с кешами шейпера (данные шрифта, планы по шрифту и письменности) и буферами `harfrust`. Повторная раскладка текста не длиннее прежнего с уже встречавшимися шрифтами и письменностями не аллоцирует; первое использование шрифта и пары «шрифт, письменность» аллоцирует один раз.
- **MSDF (#109)** — `fdsm` (MIT): контуры глифа из `skrifa` (`OutlinePen`) с той же вариацией переводятся в `fdsm::Shape` (`ttf-parser` у `fdsm` — только dev-зависимость). Ключ глифа — `(FontId, вес, glyph id)`; размер в пикселях в ключ не входит.
- **Позже:** двунаправленный текст (bidi), системный фолбэк для CJK (`fontdb`), кеш MSDF на диске, WOFF2, курсив, оси кроме `wght`.

## Последствия
- Два шрифта добавляют к бинарнику ~0,9 МБ, зато подмножеств и шага сборки нет.
- Метрики строки у основного шрифта: глиф фолбэка с большими выносными элементами может выйти за строку.
- Шейпинг абзаца до переноса не пересчитывается по строкам. Лигатуры и кернинг через точку разрыва остаются, для латиницы и кириллицы разницы нет.
- Скрипт прогона угадывается по первому сильному символу (`guess_segment_properties`). Смесь письменностей с одним направлением в одном шрифте шейпится одним прогоном.
- Пока нет bidi, изолирующие метки Fluent (FSI/PDI) не нужны и выключены в `slam-ui`.

## Отвергнутые варианты
- `cosmic-text`: полный стек (`fontdb`, `swash`, растеризация, свой кеш, редактор). Нам нужны только шейпинг и раскладка поверх контуров. Его кеш и раскладку трудно сделать безаллокационными, а растеризатор лишний.
- `rustybuzz` + `ttf-parser`: зрелые, но заброшены (RUSTSEC-2026-0206, -0192) — начинать на них новый код и держать исключения в `deny.toml` незачем.
- Подмножество шрифтов при сборке: экономит сотни килобайт, но нужен инструмент сабсеттинга и пересборка при каждом добавлении символов.
- Inter, Manrope: подходят по лицензии и кириллице, выбран Nunito Sans.

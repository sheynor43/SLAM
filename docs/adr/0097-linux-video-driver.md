# ADR-0097: Выбор видеодрайвера SDL на Linux

- Статус: Принято
- Дата: 2026-11-04
- Дополняет [ADR-0094](0094-windows-key-block.md): через Wayland блокировка сочетаний доходит до композитора

## Контекст
На Linux SDL сам выбирает видеодрайвер. Под некоторыми Wayland-композиторами (niri) он берёт X11 через Xwayland. Через X11 захват клавиатуры (ADR-0094) не доходит до композитора, и путь презентации кадра другой. Сейчас другой драйвер можно получить только переменной окружения `SDL_VIDEO_DRIVER`, а игрок о ней не знает.

## Решение
- **Настройка.** `[window] video_driver` в `slam.toml`: `auto` (по умолчанию), `wayland`, `x11`. Неизвестное значение читается как `auto`. В разделе экрана есть строка «Видеодрайвер (Linux)», видна только на Linux. Это первая строка с пометкой «после перезапуска»: драйвер выбирается один раз при `SDL_Init`, а переподнимать окно и контекст рендера на лету ради редкой настройки не стоит.
- **Применение.** Оболочка после загрузки настроек передаёт выбор в `slam-input` (`set_video_driver`, атомик). Окно читает выбор при инициализации SDL. `Auto` хинт не ставит, и SDL выбирает драйвер сам. `Wayland` или `X11` ставят `SDL_HINT_VIDEO_DRIVER` до `SDL_Init`. Команды `play`, `click`, `bench` настройки не читают, у них остаётся `Auto`.
- **Переменная окружения важнее настройки.** Если задана `SDL_VIDEO_DRIVER` или старая `SDL_VIDEODRIVER` (её SDL3 тоже читает), хинт не ставится, SDL берёт значение из окружения. Пустая переменная тоже считается заданной: SDL отказывает хинту, пока переменная есть. Так её можно и дальше использовать для отладки и замеров.
- **Откат.** Если выбранный драйвер не запустился (например, `wayland` в сеансе X11), SDL останавливается, в лог пишется предупреждение, и инициализация повторяется без хинта. Откат действует только на запуск: настройка в файле не меняется. Ошибка `Auto` или драйвера из окружения не повторяется.

## Последствия
- На niri можно выбрать Wayland, и блокировка сочетаний во время игры заработает без переменных окружения.
- Значение по умолчанию остаётся `auto`. Включать Wayland по умолчанию сейчас рискованно: SDL выбирает X11 под некоторыми композиторами не случайно (например, из-за отсутствия протоколов), а проверено это только на niri.
- Откат ловит только ошибку `SDL_Init`. Если драйвер запустился, но окно или контекст рендера не создались, повтора нет, и настройку придётся поправить в `slam.toml` вручную.
- Работающий драйвер виден в логе (строка `system shortcuts block` из ADR-0094).
- Логика выбора и отката — чистые функции, они проверены юнит-тестами. Настоящий откат на SDL в CI не проверить: без дисплея `Auto` тоже не запускается.

## Отвергнутые варианты
- **Сразу по умолчанию Wayland, если есть `WAYLAND_DISPLAY`.** Меняет поведение для всех без проверки на других композиторах. Можно вернуться к этому, когда наберётся опыт.
- **Применять сразу, пересоздавая окно.** Нужно остановить рендер, уничтожить контекст и окно, перезапустить SDL. Много кода и рисков ради настройки, которую меняют один раз.
- **Настройка важнее переменной окружения.** Тогда переменная перестаёт работать для отладки, а отключить настройку без правки файла нельзя.

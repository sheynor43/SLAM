# ADR-0166: Настройка OpenTabletDriver из SLAM через IPC демона

- Статус: Принято
- Дата: 2026-11-21

## Контекст
Большинство игроков на планшетах пользуются OpenTabletDriver (OTD, LGPL-3.0). Чтобы поменять область или фильтр, приходится сворачивать игру и открывать интерфейс OTD. OTD устроен как демон (`OpenTabletDriver.Daemon`) и клиенты (UX, консоль), которые управляют им по IPC. SLAM может стать ещё одним таким клиентом, без своего драйвера и без кода OTD.

Протокол OTD 0.6.x (сверено по исходникам v0.6.8.1 и живому демону 0.6.8.1):
- Транспорт — именованный канал .NET `OpenTabletDriver.Daemon`: на Windows `\\.\pipe\OpenTabletDriver.Daemon`, на Linux и macOS — Unix-сокет `<TMPDIR или /tmp>/CoreFxPipe_OpenTabletDriver.Daemon`. Канал создаётся с `CurrentUserOnly`.
- Сообщения — JSON-RPC 2.0 библиотеки StreamJsonRpc: заголовок `Content-Length: N\r\n\r\n`, затем тело в UTF-8. Методы — имена методов `IDriverDaemon` (`GetApplicationInfo`, `GetTablets`, `GetSettings`, `SetSettings`, …), параметры — массив. События демона (`Message`, `TabletsChanged`, `Resynchronize`, `DeviceReport`) приходят уведомлениями без `id`.
- `GetSettings`/`SetSettings` передают настройки целиком: профили по планшетам (режим вывода, область экрана и планшета, относительный режим, фильтры, привязки кнопок), инструменты, флаги блокировок.
- Сохраняет настройки на диск **клиент**: UX пишет `settings.json` по пути из `GetApplicationInfo().SettingsFile` и затем вызывает `SetSettings`. Демон сообщает остальным клиентам `Resynchronize`.
- Описания параметров фильтров и режимов вывода (тип, диапазон, подпись, единицы) демон **не отдаёт**: UX получает их рефлексией по сборкам плагинов. В настройках есть только путь типа (`Path`), флаг `Enable` и значения `{Property, Value}` тех фильтров, что UX уже записал в профиль. Список установленных режимов вывода демон тоже не отдаёт.
- OTD 0.7 ещё не выпущен; его протокол другой (сервис плагинов, другая модель настроек).

## Решение
- **Поддерживается OTD 0.6.x** (проверено на 0.6.8.1). Версия читается из `GetApplicationInfo`; при другой мажорной или минорной версии (0.7 и новее) раздел показывает «версия OTD не поддерживается» и ничего не меняет. Поддержка 0.7 — отдельным решением после его выхода.
- **Новый крейт `slam-otd`** без зависимостей от других крейтов SLAM (только `serde_json`, `thiserror`, `tracing`): транспорт, кодирование сообщений, клиент JSON-RPC, модель настроек и фоновый рабочий поток. От него зависит только `slam-app`.
- **Подключение на операцию.** Рабочий поток открывает канал на каждую команду («обновить», «применить»), выполняет вызовы и закрывает канал. Так уведомления демона не копятся в непрочитанном канале, а синхронное чтение и запись на Windows не нужно делить между потоками. Уведомления, пришедшие между ответами, пропускаются. Обновление — при открытии раздела и кнопкой «Обновить»; периодического опроса нет (каждое подключение пишет строку в лог OTD).
- **Без демона** (канала нет, отказ в подключении, тайм-аут 2 с) раздел показывает подсказку «OpenTabletDriver не запущен» и кнопку «Обновить»; остальная игра работает как прежде. Ошибки RPC показываются строкой в разделе и пишутся в лог.
- **Настройки не теряются.** Модель хранит ответ `GetSettings` деревом JSON и меняет в нём только редактируемые поля; всё остальное (привязки, инструменты, неизвестные поля, другие профили) уходит обратно как пришло. Применение: записать `settings.json` по пути из `GetApplicationInfo` через временный файл и переименование, затем `SetSettings`, затем `GetSettings` для подтверждения. Формат файла — JSON с отступом в 2 пробела и прежним порядком полей (как у Newtonsoft `Indented`). Изменения копятся в черновике и уходят в демон по кнопке «Применить»; «Сбросить» перечитывает настройки демона.
- **Что редактируется** (по профилю выбранного подключённого планшета; профили отключённых планшетов не трогаются):
  - область планшета (ширина, высота, центр X/Y в мм, поворот) с предпросмотром на схеме рабочей поверхности планшета (размеры — `Specifications.Digitizer` из `GetTablets`);
  - область экрана (ширина, высота, центр X/Y в пикселях виртуального экрана OTD);
  - флаги ограничения курсора областью (`EnableClipping`), ограничения ввода областью (`EnableAreaLimiting`) и сохранения пропорций (`LockAspectRatio`);
  - чувствительность X/Y и поворот относительного режима;
  - режим вывода: известные встроенные (`AbsoluteMode`, `RelativeMode`, на Linux `LinuxArtistMode`) плюс текущий, если он другой (показывается по последнему сегменту пути);
  - фильтры профиля: включение и выключение, значения параметров по типу из JSON (число с плавающей точкой, целое, флаг; строки и прочее — только показ). Подписи — имена свойств и последний сегмент пути типа, диапазонов нет. Добавить фильтр, которого ещё нет в профиле, нельзя (нет описания его параметров) — это делается в UX OTD.
- **Потоки.** IPC только в рабочем потоке `slam-otd`; интерфейс отправляет команды и забирает события из каналов `std::sync::mpsc` без блокировок в update-тике и кадре (`try_recv`). Поток создаётся при первом показе раздела и живёт до выхода (не присоединяется: зависший на Windows вызов не держит выход). Приём нового состояния демона (копия черновика, имена строк) выделяет память на update-потоке — это бывает только по «Обновить» и «Применить», как навигация.
- **Раздел настроек «Планшет»** со своим значком (ADR-0165), перед «Связью»; все строки — ключи Fluent. Строки раздела идут после `Row::ALL` неизменным набором, лишние скрываются:
  - заметки о состоянии (демон не найден, версия не поддерживается, нет планшета с профилем, ошибка); пока демон не отвечает или его версия не та — кнопка «Скачать с официального сайта» (`https://opentabletdriver.net/`, открывается в браузере, как ссылки раздела «Связь»); кнопки «Обновить», «Применить», «Сбросить»;
  - имя планшета (при нескольких подключённых — кнопка «Следующий»), режим вывода (встроенные режимы и «Другой (плагин)», который режим не меняет);
  - группы с заголовками-заметками: «Область планшета» — схема (строка `Preview` высотой в четыре строки: рабочая поверхность и повёрнутая область), ширина, высота, центр, поворот (диапазон — размеры поверхности из `GetTablets`, шаг 0,01 мм), «Сохранять пропорции» (сторона области планшета следует за другой по пропорциям области экрана, как в UX OTD); «Область экрана» — ширина, высота, центр (0–16384 пкс, диапазон расширяется до значения: отрицательные центры мониторов слева на Windows), ограничение курсора и ввода; «Относительный режим» — чувствительность X/Y и поворот;
  - «Установленные фильтры»: до 6 фильтров профиля, у каждого переключатель (вкл./выкл.), а под включённым фильтром — его параметры (до 12): число — ползунок, флаг — переключатель; у выключенного параметры скрыты, их значения в черновике сохраняются. Диапазон ползунка параметра берётся от значения на момент приёма состояния: [0; 1] для значений из [0; 1], иначе до ближайшей степени десяти не меньше удвоенного значения (отрицательные — симметрично); целые остаются целыми в JSON.
  - Имена планшета, фильтров и параметров — данные демона, не переводятся; они подставляются в подписи строк на ходу (`SettingsScreen::set_dynamic_labels`, текст до 64 байт в заранее выделенном и «прогретом» самой длинной строкой буфере, перекладка только при новых именах), диапазон ползунка меняется `set_slider_range`. Экран настроек вмещает до 304 строк (`MAX_ROWS`).
- **Демон спрашивается при показе раздела**, а не при каждом открытии панели: один раз за открытие, и не поверх неприменённых правок (их перечитывает только «Обновить»). Пока команда в пути, редактирующие строки заблокированы (ответ заменяет черновик). Не ответивший за 10 с рабочий поток бросается (на Windows чтение канала без тайм-аута): раздел показывает ошибку, следующий запрос создаёт новый поток.
- **Защита записи.** На Linux сокет лежит в общем `/tmp`: доверяется только сокет, принадлежащий игроку. Путь из `GetApplicationInfo` принимается, только если это абсолютный путь к `settings.json`. При записи симлинк сохраняется (заменяется его цель), права прежнего файла переносятся. Если `SetSettings` после записи файла не прошёл, файл уже новый — демон подхватит его при следующем запуске; раздел показывает ошибку.
- **Аллокации.** Приём состояния демона и правка черновика (дерево JSON, разбор профиля) выделяют память на update-потоке. Это бывает только по действиям игрока в открытой панели настроек, как навигация; без новостей опрос рабочего потока не выделяет.

## Последствия
- Область и фильтры меняются без выхода из игры; профили и привязки OTD сохраняются.
- Параметры фильтров без диапазонов и человекочитаемых подписей; новые фильтры добавляются только в UX OTD.
- Настройки, изменённые в UX OTD при открытом разделе, видны после «Обновить»; «Применить» поверх них перезапишет их черновиком SLAM.
- Работа с Windows-каналом проверяется вручную на Windows (пока не проверена).

## Отвергнутые варианты
- **Встроить OTD или загружать его сборки.** Нужен .NET-рантайм внутри игры и связка с LGPL-кодом; IPC проще и не зависит от версии сборок.
- **Своя рефлексия плагинов** (читать метаданные .NET из `.dll` в папке плагинов ради диапазонов и подписей). Большой разборщик метаданных CLI ради подписей; можно вернуться позже.
- **Постоянное подключение с чтением событий.** На Windows синхронный канал нельзя одновременно читать и писать из разных потоков, а асинхронный ввод-вывод — заметно больше кода; выгода (мгновенное `TabletsChanged`) невелика.
- **Писать `settings.json` напрямую без демона.** Демон не перечитывает файл сам — изменения не применились бы до перезапуска.

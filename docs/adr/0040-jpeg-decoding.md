# ADR-0040: Декодирование JPEG крейтом `zune-jpeg`, выбор декодера по сигнатуре файла

- Статус: Принято
- Дата: 2026-10-14
- Дополняет [ADR-0034](0034-texture-loading.md) (не заменяет)

## Контекст
Фоны карт почти всегда JPEG, а ADR-0034 отложил JPEG: загрузчик текстур умеет только PNG (`decode_png`). Для #130 (фон с затемнением) и #95 (выбор карты) JPEG нужен сейчас.

osu-framework декодирует изображения через stb_image (при ошибке — ImageSharp) и формат определяет по содержимому файла, а не по расширению: карта с `bg.jpg`, внутри которого PNG, у лазера показывает фон.

## Решение
- **Крейт `zune-jpeg` 0.5** (MIT OR Apache-2.0 OR Zlib, чистый Rust, SIMD для x86/NEON). Поддерживает baseline и progressive, субдискретизацию, серые, YCbCr, CMYK/YCCK. В 0.5.15 перевод CMYK сразу в RGBA сломан — четырёхкомпонентные файлы декодируются в RGB и расширяются до RGBA у нас.
- **`decode_jpeg(bytes, limits)`** в `slam-render::image` — рядом с `decode_png`, с тем же контрактом: результат `Image` в `Rgba8` с альфой 255; сначала читается заголовок, и сторона больше `max_side` или размер результата больше `max_bytes` — ошибка до выделения памяти под пиксели (сам декодер держит ещё свои буферы: у progressive — коэффициенты по 2 байта на компоненту, у CMYK — промежуточный RGB, так что пик памяти до ~2,5 × `max_bytes`); битый файл — ошибка, не паника. Метаданные (EXIF-ориентация, ICC) игнорируются, как у stb_image.
- **`decode_image(bytes, limits)`** выбирает декодер по сигнатуре: `89 50 4E 47 0D 0A 1A 0A` — PNG, `FF D8 FF` — JPEG, иначе ошибка `Unsupported`. Расширение файла не учитывается. Поток загрузки текстур (ADR-0034) вызывает `decode_image` вместо `decode_png`; остальной путь (раскладка, выгрузка полосами, бюджет) не меняется.

## Последствия
- Фоны карт и JPEG-элементы скинов грузятся тем же потоком загрузки; фон 1920×1080 декодируется в нём, выгрузка — по-прежнему ≥ 4 кадров при бюджете 2 МБ.
- Новая зависимость `zune-jpeg` (+ `zune-core`), без системных библиотек.
- Паритет пикселей с stb_image не гарантирован: апсемплинг цветности и IDCT могут отличаться на единицы уровня канала — для фонов это не важно.
- Другие форматы (BMP, GIF, WebP) — по мере необходимости тем же диспетчером.

## Отвергнутые варианты
- `jpeg-decoder`: в режиме поддержки, крейт `image` сам перешёл на `zune-jpeg`; медленнее.
- `image` с фичей `jpeg`: тянет `zune-jpeg` всё равно плюс общий слой `DynamicImage` с лишними копиями; лимиты до выделения памяти проще контролировать напрямую.
- `turbojpeg`/`mozjpeg`: системная C-библиотека, сложнее сборка на Windows.
- Выбор декодера по расширению: карты с неверным расширением у нас не показали бы фон, у лазера показывают.

# ADR-0143: Лог в файл и окно фатальной ошибки

- Статус: Принято
- Дата: 2026-11-15
- Уточняет ADR-0068 (альфа-сборки: на Windows нет консоли)

## Контекст
Релизная сборка на Windows — GUI-приложение без консоли (ADR-0068): лог виден, только если запустить игру из терминала. Вылет при запуске (#369) не оставляет следов, а просить игроков запускать игру из `cmd` — плохой способ собирать отчёты.

## Решение
- **Лог в файл.** Обычный запуск игры пишет лог `tracing` одновременно в консоль и в `<данные>/logs/slam.log` (ARCHITECTURE §17), в файл — без цветовых кодов. Каждое событие записывается в файл сразу, одним вызовом записи, без буфера и без блокировки, поэтому лог доходит до последней строки и при падении без паники (сбой драйвера, переполнение стека). Отладочные команды (`bench`, `play`, `screenshot` и т. п.) пишут только в консоль.
- **Ротация** при запуске: `slam.log` → `slam.1.log` → … → `slam.4.log`, хранятся пять последних запусков. Первые строки лога — версия, ОС и архитектура, аргументы.
- **Паника** любого потока записывается в лог через `tracing` с местом, именем потока и бэктрейсом; стандартный обработчик паники заменяется, чтобы сообщение не печаталось дважды.
- **Окно ошибки.** Если паникует главный поток или запуск игры завершается ошибкой, показывается системное окно с текстом ошибки и путём к логу: `SDL_ShowSimpleMessageBox`, которому не нужна инициализация SDL и которое есть на Windows и Linux. Строки окна — ключи Fluent; язык берётся из `slam.toml`, если его удалось прочитать, иначе английский.
- **Проверочная паника.** Переменная окружения `SLAM_DEBUG_PANIC` (в том числе в релизной сборке) вызывает панику главного потока при запуске — чтобы проверить окно и лог на любой машине.

## Последствия
- В отчёте об ошибке достаточно приложить `logs/slam.log` из папки данных; README говорит об этом вместо запуска из терминала.
- Горячие пути не логируют; запись в файл не берёт блокировок.
- Бэктрейс на Windows читает имена функций из `slam.pdb` рядом с `slam.exe`, поэтому PDB кладётся в портативный архив; без него в бэктрейсе только адреса.
- Паника потока update или draw закрывает окно игры (поток движка при выходе ставит флаг, наблюдатель оболочки закрывает окно), `Engine::shutdown` переносит панику в главный поток — и показывается окно ошибки. Паника аудиопотока внутри колбэка драйвера завершает процесс аварийно; она успевает попасть в лог, окна нет.
- При аварийном выходе несохранённые правки настроек теряются; уже записанные файлы не портятся (запись через временный файл).
- Паника записывается в лог при любом `RUST_LOG`: фильтр всегда пропускает ошибки модуля лога.

## Отвергнутые варианты
- `tracing-appender` с фоновым потоком записи: при аварийном завершении процесса последние строки, как раз самые нужные, теряются.
- Имена файлов с датой: нужна зависимость для времени, а пяти последних запусков хватает для отчёта.
- `MessageBoxW` только на Windows: окно SDL одинаково на обеих ОС и проверяется на Linux.

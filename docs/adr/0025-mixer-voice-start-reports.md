# ADR-0025: Отчёты микшера о старте голосов

- Статус: Принято
- Дата: 2026-10-10
- Дополняет [ADR-0023](0023-hitsound-mixer.md) (не заменяет)

## Контекст
Для сквозного замера «клик → звук» (#26) нужно знать, в каком буфере реально начал звучать поставленный в очередь хитсаунд и когда этот буфер выйдет из устройства. Микшер из ADR-0023 сообщает только счётчики (`MixerStats`): по ним нельзя сопоставить конкретную команду `play` с буфером. Аудиопоток не может логировать, аллоцировать и брать блокировки.

## Решение
- **Опционально.** `MixerConfig::start_reports` — ёмкость кольца отчётов; 0 (по умолчанию) отключает отчёты, и обычная игра за них не платит.
- **Отчёт** `VoiceStart`: порядковый номер команды `play` (с нуля, по всем принятым в очередь командам `play`), а также `frame`, `timestamp_ns` и `latency_ns` из `CallbackInfo` буфера, с первого кадра которого голос зазвучал. Оценка выхода звука — `timestamp_ns + latency_ns` (при `timestamp_ns = 0` оценки нет).
- **Нумерация без изменения API.** `play` по-прежнему возвращает `Result<(), PlayError>`. Хэндл считает принятые команды `play` (`MixerHandle::queued_plays`); микшер считает их в том же порядке (SPSC). Номер только что поставленной команды — `queued_plays() − 1`. Пустой сэмпл в очередь не ставится и номера не получает.
- **Передача.** Колбэк кладёт отчёт в отдельное SPSC-кольцо `rtrb`, выделенное при создании микшера; `MixerHandle::drain_started(f)` вызывает `f` на каждом отчёте в update-потоке. При полном кольце отчёт отбрасывается, `MixerStats::start_report_overflows` увеличивается. Голос при этом звучит как обычно.
- Отчёт пишется и тогда, когда голос сразу же вытесняет другой. Если формат потока разошёлся с микшером (буфер тишины), команды всё равно применяются и отчёт пишется для этого буфера — так же, как сейчас запускается голос.

## Последствия
- Замер «постановка в очередь → начало буфера» и «→ выход из устройства» возможен по каждому клику без логирования в аудиопотоке.
- В колбэке +1 проверка на команду `play` и одна запись в кольцо при включённых отчётах; без них — только проверка.
- Если читатель не опустошает кольцо, отчёты теряются (счётчик), а не блокируют микшер.
- Отчёт о старте в буфере с несовпадающим форматом называет этот (тихий) буфер, а голос звучит со следующего подходящего: оценка опаздывает минимум на буфер. С PipeWire недостижимо — формат потока и микшера берётся из одной конфигурации.
- Голос, вытесненный в том же буфере, в котором стартовал (больше 6 копий сэмпла за буфер), получает отчёт, но не звучит.
- Бэкенд берёт таймстемп буфера в начале цикла графа, до того как колбэк разбирает команды, поэтому команда, поставленная в этом промежутке, звучит в буфере, чей таймстемп раньше постановки. Для замеров надёжна разность «выход − постановка», а не «таймстемп буфера − постановка».
- Точность оценки выхода ограничена тем, насколько верна задержка, которую сообщает бэкенд; это и проверяется физическим замером в #26.

## Отвергнутые варианты
- **`play` возвращает идентификатор голоса.** Ломает API и усложняет случай пустого сэмпла; нумерация по счётчику даёт то же самое.
- **Таймстемп постановки в команде.** Микшеру он не нужен; хэндл и так знает момент постановки, а сопоставление по номеру проще.
- **Атомик «последний старт» вместо кольца.** Теряет отчёты при нескольких командах в одном буфере (двойной клик, клавиша + мышь).
- **Всегда включённые отчёты.** Лишняя работа в колбэке и кольцо, которое никто не читает, в обычной игре.

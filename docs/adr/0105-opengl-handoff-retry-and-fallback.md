# ADR-0105: Запуск OpenGL — повтор привязки контекста, проверка передачи потоку отрисовки и откат на Direct3D 11

- Статус: Принято
- Дата: 2026-11-07
- Уточняет [ADR-0104](0104-renderer-setting-opengl-default.md) (пункт «Отката с OpenGL на D3D11 нет»). Закрывает [#323](https://github.com/sheynor43/SLAM/issues/323).

## Контекст
На Windows 11 (RX 6700 XT) OpenGL упал при старте 2 раза из ~6 запусков подряд, оба раза сразу после закрытия предыдущего окна SLAM. Ошибка — `wglMakeCurrent(): ERROR_TRANSFORM_NOT_SUPPORTED`. Следующий запуск проходил нормально, значит сбой временный.

Падает не создание контекста. Контекст создаётся на главном потоке, там же создаётся пробное устройство (ADR-0080), и это проходит. Сбой случается, когда поток отрисовки впервые делает контекст текущим (ADR-0018). Ошибка там необратима: окно уже открыто под OpenGL, сцены мономорфизированы по бэкенду, а поток отрисовки на ней паникует.

После ADR-0104 OpenGL — рендер по умолчанию на Windows. Сбой при запуске по умолчанию недопустим. Воспроизвести его на Linux нельзя, а проверка на Windows не гарантирует, что временный сбой там встретится.

## Решение
- **Повтор привязки.** `GlContext::make_current` при ошибке SDL повторяет вызов до 5 попыток, с паузами 10, 20, 40 и 80 мс (всего ~150 мс). Каждая неудача пишется в лог `warn` с текстом SDL (в нём есть сообщение `GetLastError`). Если все попытки не удались, возвращается последняя ошибка. Ошибка «контекст текущий на другом потоке» не повторяется: это ошибка вызывающего кода. Так же повторяется `release_current`: контекст, оставшийся текущим на завершившемся потоке, нельзя ни уничтожить, ни сделать текущим снова, и откат на D3D11 после этого не открыл бы окно. `make_current` вызывается только при создании устройства, а не в кадре, поэтому пауза горячего пути не касается. Повтор работает на всех ОС; на Linux реальная ошибка просто приходит на ~150 мс позже.
- **Проверка передачи.** `Backend::open` для OpenGL после пробного устройства передаёт контекст короткоживущему потоку. Тот делает контекст текущим (с тем же повтором) и отпускает его. Так на главном потоке, до запуска отрисовки, проверяется тот же путь, на котором произошёл сбой. Ошибка здесь — ошибка `open`.
- **Откат на D3D11.** `Renderer::Auto` (настройка `"opengl"`, по умолчанию, и `--renderer auto`): на Windows, если OpenGL не открылся (контекст, пробное устройство или проверка передачи), в лог пишется причина, окно OpenGL закрывается и открывается D3D11. Вне Windows `Auto` — только OpenGL, как раньше. Настройка при откате не меняется (как у отката D3D11 → OpenGL в ADR-0104).
- **`--renderer opengl`** у `bench` и `play` — OpenGL без отката, для замеров (как `--renderer d3d11`, ADR-0080).
- Если сбой всё же случится на потоке отрисовки после успешной проверки (повтор не помог), поведение прежнее — паника потока отрисовки с текстом ошибки.

## Последствия
- Временный сбой `wglMakeCurrent` перекрывается повтором. Если он постоянный, игра стартует на D3D11, а не падает.
- Запуск при сбое удлиняется до ~150 мс на каждой из двух привязок. Нормальный запуск — на одно создание потока и две привязки контекста, это доли миллисекунды.
- Причина сбоя в драйвере не найдена: без Windows её не выяснить. Лог показывает, сработал ли повтор (`warn` с номером попытки) и был ли откат.
- Проверка на Windows не обязательна для закрытия #323. Тесты проверяют логику повторов и выбор отката с подставными функциями. Реальную передачу контекста потоку проверяет тест с окном на Linux (`slam-app/tests/gl_open.rs`, запускается вручную, как другие тесты с окном).
- Отката с OpenGL на D3D11 после старта потока отрисовки нет: для этого нужно пересоздавать окно и сцены.

## Отвергнутые варианты
- **Только повтор, без отката.** Если сбой окажется не временным у части игроков, игра по умолчанию не запустится.
- **Откат прямо из потока отрисовки.** Поток отрисовки и сцены уже созданы под OpenGL (мономорфизация, ADR-0080). Нужно вернуть ошибку на главный поток, закрыть окно, открыть новое под D3D11 и пересоздать сцены. Это крупная переделка ради сбоя, который проверка передачи ловит раньше.
- **Не передавать контекст между потоками** (создавать его сразу на потоке отрисовки). Окна SDL создаются на главном потоке, и ADR-0018 держит создание контекста там же. Пересмотр — отдельный ADR, если сбой не уйдёт.
- **Выяснить причину на Windows до исправления.** Сбой непостоянный, 20 запусков ничего не гарантируют. Повтор с откатом закрывает его в любом случае.

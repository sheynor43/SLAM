# ADR-0109: Раскладки HUD — охват, пресет SLAM, формат хранения и экспорта

- Статус: Принято
- Дата: 2026-11-09
- Дополняет [ADR-0061](0061-hud-layout-presets.md), [ADR-0052](0052-gameplay-menu-overlay.md), [ADR-0015](0015-hud.md)

## Контекст
ADR-0061 оставил открытые вопросы до начала работы над раскладками: каким будет пресет SLAM, как называется файл экспорта, распространяется ли раскладка за пределы HUD игры и какая раскладка включается для скинов lazer со своей JSON-раскладкой. Раскладки перенесены в M3 (#216), без них скины lazer не загружаются целиком. Сейчас HUD нарисован по константам в `slam-play` (`hud.rs`), модели раскладки нет.

## Решение
- **Охват.** Раскладка описывает три экрана: HUD игры (`gameplay`), меню паузы и окно провала (`pause`), экран результатов (`results`). Меню паузы и провала по-прежнему не компоненты HUD: состояние и поведение остаются в `PlaySession` (ADR-0052). Раскладка задаёт только положение и вид их элементов. Выбор песни и прочие меню раскладка не описывает.
- **Пресет SLAM** — раскладка stable плюс unstable rate, счётчик клавиш и pp-каунтер. Пресеты stable и lazer повторяют HUD соответствующего клиента. Пока у SLAM нет этих компонентов, пресеты описывают только то, что HUD уже умеет рисовать; недостающие элементы добавляются вместе с компонентами.
- **Модель элемента:**
  - вид компонента;
  - привязка и origin (9 точек каждая);
  - смещение в единицах экрана 640×480 (как в stable и в HUD JSON лазера);
  - масштаб;
  - поворот в градусах;
  - прозрачность;
  - видимость;
  - наклон для перспективы (хранится, применяется с M5);
  - необязательный свой спрайт — имя файла в папке раскладки;
  - свойства компонента — словарь «ключ → значение».

  Неизвестный вид компонента и неизвестные свойства при чтении сохраняются как есть: раскладка из более новой версии SLAM не теряет данные при правке в старой.
- **Хранение.** Своя раскладка — папка `<data>/hud-layouts/<id>/`, в ней `layout.json` и `sprites/`. Встроенные пресеты вшиты в программу, у них id `builtin:stable`, `builtin:lazer` и `builtin:slam`. Встроенные нельзя переименовать, изменить или удалить, только дублировать. Дублирование создаёт новую свою раскладку с новым id и копирует спрайты.
- **Версия формата.** В `layout.json` есть поле `version`, текущая версия — 1. Раскладка с версией новее поддерживаемой не загружается: ошибка с номером версии. Старые версии мигрируют при чтении.
- **Экспорт** — один файл `.slamhud`: zip-архив с `layout.json` и `sprites/`. Своё расширение позволяет открыть файл двойным щелчком, как `.osk`.
- **Скины lazer.** Смена скина не меняет активную раскладку, даже если у скина есть своя JSON-раскладка HUD. При выборе такого скина игроку предлагается импортировать её в свою раскладку.

## Последствия
- Модель раскладки и встроенные пресеты живут в `slam-ui` (HUD и его редактор, ARCHITECTURE §3). Чтение и запись папок раскладок — в `slam-app`. Разбор HUD JSON лазера — в `slam-formats`.
- Отрисовка HUD, паузы и результатов переходит с констант на раскладку отдельными задачами. До этого пресеты хранятся, но не влияют на экран.
- Импорт `.slamhud` проверяет размер и формат спрайтов так же, как файлы скина (ADR-0061).
- Раздел «раскладки HUD» в `.slamcfg` (ADR-0013) пакует папки так же, как `.slamhud`.

## Отвергнутые варианты
- **Пресет SLAM — минимальный HUD без здоровья и прогресса.** Игрок выбрал привычную раскладку stable с дополнительными счётчиками; минимальный HUD собирается дублированием.
- **Экспорт обычным `.zip`.** Не ассоциируется с программой, его легко спутать с архивом скина.
- **Только HUD игры.** Пауза и результаты тоже скинуются и раскладываются по-разному в stable и lazer; один формат для всех трёх экранов проще, чем второй формат позже.
- **Пресет lazer по умолчанию для скинов с JSON-раскладкой.** Смена скина меняла бы HUD, что противоречит ADR-0061.

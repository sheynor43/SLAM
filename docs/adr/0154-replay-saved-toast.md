# ADR-0154: Уведомление о сохранённом реплее

- Статус: Принят
- Дата: 2026-11-16

## Контекст
Реплей сохраняется молча: игрок не знает, где файл. В лазере после сохранения появляется уведомление, по клику файл показывается в файловом менеджере (`PresentFileExternally`); в stable — всплывающее сообщение, по клику открывается папка.

## Решение
- **Уведомление** (`slam_ui::toast`) — плашка в правом нижнем углу поверх всех экранов (над шторкой, как оверлей громкости): заголовок «Реплей сохранён» и подсказка «Нажмите, чтобы показать файл» (Fluent). Выезжает справа и проявляется (`toast_in_ms`), висит `toast_show_ms` (5 с; пока над ней курсор — не прячется), уходит за `toast_out_ms`. Новое сохранение показывает уведомление заново.
- **Клик** по плашке забирает нажатие (под ней ничего не нажимается), прячет уведомление и показывает файл: Linux — `org.freedesktop.FileManager1.ShowItems` через `dbus-send`, при неудаче `xdg-open` на папку; Windows — `explorer /select,`; macOS — `open -R`. Запуск — в отдельном потоке, как открытие ссылок (`feedback`), update-поток не ждёт.
- **Путь** приходит из потока загрузчика, который сохраняет реплей, по кольцу в update-поток; прежний путь уходит обратно в загрузчик через кольцо мусора (`Trash::Path`), так что тик не освобождает память. Autoplay реплей не сохраняет (ADR-0153) — уведомления нет.

## Последствия
- Клик по уведомлению аллоцирует (копия пути и поток) — один раз на действие игрока, как открытие ссылок.
- Открытие файлового менеджера на Windows и macOS не проверено.

## Отвергнутые варианты
- **Общий центр уведомлений, как в лазере.** Пока нужно одно уведомление; центр — когда их станет больше.
- **Копировать путь в буфер обмена.** Игроку нужен файл, а не строка.

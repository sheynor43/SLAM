# ADR-0068: Сборка альфа-релиза

- Статус: Принято
- Дата: 2026-10-25

## Контекст
Первая альфа (#232) уходит тестерам на Linux и Windows. Собранный бинарник должен работать вне дерева исходников. Шрифты, локали и шейдеры уже встроены (`include_bytes!`, `include_str!`, build-скрипты), а дефолтный скин (`assets/default-skin`, ~13 МБ, ~180 файлов) читается с диска по пути `CARGO_MANIFEST_DIR`, зафиксированному при сборке. `Skin` хранит пути к файлам, потребители (хитсаунды, текстуры, фон) читают файлы сами — источника в памяти у скина нет. ARCHITECTURE §19 обещает AppImage на Linux и портативный архив на Windows.

## Решение
- **Версия** — `0.0.1-alpha` в `[workspace.package]`; тег релиза `v0.0.1-alpha`.
- **Скин встроен и распаковывается.** `slam-app/build.rs` перечисляет `assets/default-skin` и генерирует таблицу `(имя, include_bytes!)` и 64-битный хеш содержимого (FNV-1a по отсортированным именам и байтам, без новых зависимостей). Модуль `default_skin` при первой загрузке карты распаковывает таблицу в `<данные>/cache/default-skin/<хеш>/`: сначала во временную папку рядом, затем `rename`; готовая папка не перезаписывается, папки других хешей удаляются. Путь вычисляется один раз за процесс. Без каталога данных — во временный каталог ОС. `Skin::load_default` и потребители не меняются.
- **Linux — AppImage.** Сборка на `ubuntu-24.04` (те же пакеты, что в CI, включая `libdbus-1-dev`), `appimagetool` закреплённой версии. В образе — бинарник `slam`, `.desktop`, иконка. SDL3 статический; PipeWire, libGL, libstdc++, D-Bus — системные (в образ не кладутся).
- **Windows — портативный `.zip`.** `slam.exe` (MSVC), лицензии (`LICENSE-MIT`, `LICENSE-APACHE`, `THIRD_PARTY_NOTICES`, лицензия скина), инструкция. Файл `portable` в архив не кладётся: настройки по умолчанию в `%APPDATA%\SLAM`.
- **Иконка** — `assets/icon/slam.png` (512×512, AppImage) и собранный из неё `slam.ico`; в `slam.exe` её встраивает `embed-resource` (MIT/Apache) только для MSVC: проверка clippy под `windows-gnu` на Linux обходится без компилятора ресурсов.
- **Без консоли на Windows.** Release-сборка — подсистема `windows`; при запуске из терминала процесс подключается к его консоли (`AttachConsole`), так что логи и вывод команд разработчика видны там. Отладочная сборка остаётся консольной.
- **Инструкция для тестеров** — `packaging/release-notes.md` на английском и русском (запуск, типичные проблемы, сбор логов, куда писать): текст pre-release и `README.md` в архивах.
- **Workflow `release.yml`** по тегу `v*`: сборки Linux и Windows параллельно, затем публикация pre-release с обоими файлами. Сборка проверяет, что в архивах нет `slam.toml`, `portable` и пользовательских данных.
- Исполняемый файл называется `slam` (`[[bin]]` в `slam-app`).

## Последствия
- Бинарник самодостаточен; размер растёт на ~13 МБ.
- Первая загрузка карты после установки или обновления пишет ~13 МБ на диск; старые версии скина удаляются.
- Пользователь, правящий распакованный скин, теряет правки при обновлении — для своих скинов есть папка `skins/`.
- AppImage зависит от glibc Ubuntu 24.04: на более старых дистрибутивах не запустится.
- Установщика Windows пока нет (§19 его обещает) — позже.

## Отвергнутые варианты
- **Папка скина рядом с exe** — меньше кода, но тогда вне дерева исходников бинарник без папки не работает, а в issue решено встраивать.
- **Источник файлов в памяти у `Skin`** — чище, но требует переделки `slam-skin`, хитсаундов и загрузки текстур; отдельная задача, если распаковка начнёт мешать.
- **Сборка на ubuntu-22.04** ради старой glibc — не проверено, собирается ли `pipewire-rs` со старым PipeWire; вернуться, если тестеры упрутся в glibc.

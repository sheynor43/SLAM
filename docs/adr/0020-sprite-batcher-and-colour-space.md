# ADR-0020: Батчер спрайтов, атлас текстур и цветовое пространство

- Статус: Принято
- Дата: 2026-10-08

## Контекст
Для #7 нужны атлас текстур и батчер спрайтов. Кадр рисуется за минимум вызовов отрисовки и без аллокаций. Перед этим нужно было закрыть два вопроса из ADR-0019 и HAL: в каком цветовом пространстве смешиваются цвета и как каждый кадр загружаются вершины. Контракт `write_buffer` позволяет писать регион не чаще раза за кадр и до первой отрисовки, которая его читает.

Как это сделано в osu-framework (эталон по LAZER_REFERENCE):
- Кадр без sRGB: `SwapchainSrgbFormat` нигде не включается, в шейдерах нет `toSRGB`/`toLinear`. Цвета вершин и текстуры смешиваются как sRGB-закодированные значения. Через линейное пространство (`SRGBColour.Linear` → `ToSRGB`) проходит только CPU-арифметика цветов (умножение, интерполяция).
- Альфа прямая (straight). `BlendingParameters.Mixture` = `SrcAlpha, OneMinusSrcAlpha` для цвета, `One, One` для альфы. Это `Blend::Alpha` в HAL.
- Атлас раскладывает изображения рядами с отступом. Вершины грузятся через `BufferSubData` в кольцо буферов, которое сдвигается на каждой отрисовке батча. Индексы квадов `ushort`, не больше 65535 вершин на батч.

## Решение
- **Цвет.** Смешивание идёт в sRGB-закодированном (гамма) пространстве, как в osu-framework: кадр и рендер-таргеты без sRGB-конверсии, текстуры скинов загружаются как `Rgba8` (значения как в файле), цвет вершины — sRGB-закодированный, straight alpha. Арифметика оттенков (`цвет × альфа родителя` и т. п.) — забота слоя сцены/UI, который передаёт батчеру уже итоговый цвет; если она нужна в линейном пространстве, она делается там, как в `SRGBColour`. `Rgba8Srgb` остаётся в HAL для данных, которым нужна линейная выборка, но для скинов не используется.
- **Вершина спрайта:** позиция `f32×2`, цвет `f32×4`, UV `f32×2` — 32 байта (цвет во float, как `TexturedVertex2D`). Координаты — пиксели цели, начало вверху слева, y вниз; проекция — uniform-буфер.
- **Запись кадра** (`SpriteBatch`) — только CPU: спрайт (позиция точки опоры, размер, точка опоры, поворот по часовой в радианах, цвет, текстура, UV-прямоугольник, режим смешивания) превращается в 4 вершины. Порядок отрисовки сохраняется; соседние спрайты с одинаковыми текстурой и смешиванием сливаются в батч. Сортировки нет. Векторы переиспользуются: после разогрева кадр не аллоцирует.
- **Текстуры в записи — по `TextureId`** (`u32`), а не по ссылке: запись живёт дольше заимствований. Владелец — `Textures<T>` (слот-вектор с переиспользованием id, без поколений: регион не должен переживать свою страницу); при отрисовке id разрешает функция вызывающего, так что можно подставить и текстуру рендер-таргета.
- **Отрисовка** (`SpriteRenderer`) — кольцо из N слотов (по умолчанию 3), в слоте вершинный и uniform-буфер. Каждый вызов отрисовки записи берёт следующий слот: одна `write_buffer` вершин, одна — проекции, затем `draw_indexed` на батч со смещением вершинного буфера. Кольцо продолжается через кадры; между `begin_frame` допускается не больше N вызовов, лишний возвращает ошибку `OutOfSlots`. Так контракт `write_buffer` (регион пишется не чаще раза за кадр) соблюдается на любом бэкенде без orphaning и fence; запасные слоты сверх числа вызовов за кадр отдаляют перезапись буфера, который GPU ещё может читать из прошлого кадра (в GL — меньше неявных синхронизаций). Не хватает места — буфер слота пересоздаётся с размером следующей степени двойки (только в неустоявшемся кадре).
- **Индексы** — один статический буфер `u16` на 16384 квада (65536 вершин). Батч длиннее делится на несколько отрисовок.
- **Атлас** — страницы одного формата (размер задаёт вызывающий, `Atlas::DEFAULT_PAGE_SIZE` = 2048×2048, не больше лимита устройства), упаковщик полками: изображение идёт на полку с наименьшей потерей высоты (не больше половины его высоты), иначе открывает новую полку. Вокруг изображения — рамка в 1 пиксель из повторённых краёв (хватает для линейной фильтрации без мипмапов). Не влезает ни в одну страницу — новая страница; больше страницы — страница, растянутая по нужной оси до размера изображения (её остаток занимают другие изображения). Размер проверяется до выделения памяти; изображение со стороной, равной лимиту устройства, не помещается вместе с рамкой. Новые страницы заполнены нулями. Для частичной загрузки в HAL добавлен `write_texture` (`COPY_DST`).
- **Статистика**: каждый вызов отрисовки записи возвращает число спрайтов, батчей и draw call — для оверлея (#8).

## Последствия
- Скины и цвета выглядят как в stable/lazer; гамма-корректного смешивания нет, как и у них.
- Нет зависимости от orphaning и fence: на D3D11/Vulkan кольцо работает так же. Цена — N копий буферов на GPU.
- Сплошные прямоугольники рисуются белым пикселем из атласа (его кладёт вызывающий), чтобы не рвать батч.
- Мипмапы, обрезка/маски, режимы wrap внутри региона атласа, загрузка из рабочих потоков с бюджетом на кадр и освобождение места в атласе — позже; рамку в 1 пиксель придётся увеличить вместе с мипмапами (в osu-framework отступ `(1 << MAX_MIPMAP_LEVELS) × MAX_EDGE_SMOOTHNESS`).

## Отвергнутые варианты
- Линейное смешивание (sRGB-кадр, `Rgba8Srgb`-текстуры): правильнее физически, но полупрозрачные элементы скинов выглядели бы иначе, чем в stable/lazer.
- Orphaning (`glBufferData(NULL)`) или persistent mapping: специфичны для GL, persistent mapping требует GL 4.4.
- Цвет вершины `Unorm8x4` (20 байт): экономит память, но теряет точность плавных затуханий относительно osu-framework.
- Сортировка спрайтов по текстуре: меняет порядок наложения.
- Упаковщик skyline/MaxRects: плотнее, но сложнее; для элементов скинов полок хватает.

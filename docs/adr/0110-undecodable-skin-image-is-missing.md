# ADR-0110: Битое изображение скина считается отсутствующим

- Статус: Принято
- Дата: 2026-11-09
- Дополняет [ADR-0058](0058-default-skin-chain.md), [ADR-0034](0034-texture-loading.md) (не заменяет)

## Контекст
Поиск текстуры в скине (`Skin::texture`, `SkinChain`) решал по индексу файлов: непустой файл есть — текстура найдена. Декодирование шло позже, в потоке `slam-texture-load` (ADR-0034), и битый файл давал `TextureState::Failed`, когда поиск уже закончен. Элемент не рисовался, хотя у скина был целый 1x-файл или целый файл в следующем скине цепочки. ADR-0058 записал это как расхождение с лазером.

В лазере `TextureLoaderStore` декодирует изображение при `Get` и при ошибке возвращает `null`. `LegacySkin.GetTexture` тогда пробует 1x-имя, а цепочка скинов — следующий скин. Выбор провайдера (`FindProvider(s => s.GetTexture("cursor") != null)`) учитывает то же самое.

## Решение
- **Битый файл — нет файла.** Файл изображения, который не декодируется (ошибка формата, обрезанные данные, превышение лимитов загрузчика), при поиске текстуры считается отсутствующим: `@2x` → 1x того же скина → то же имя в следующем скине цепочки. Это касается всех путей поиска: `texture`, `animation` (битый кадр, как отсутствующий, обрывает последовательность кадров), `provides_animation`, выбор провайдера. Внутри одного имени расширения не перебираются дальше: если первый найденный файл (`name`, `name.png`, `name.jpg`) битый, имя не найдено — как `ResourceStore.GetStream` отдаёт первый существующий поток, а `TextureLoaderStore.Get` при ошибке возвращает `null`.
- **Проверку задаёт вызывающий.** `slam-skin` не декодирует изображения и не зависит от `slam-render` (ARCHITECTURE §3). Скину передаётся проверка `Fn(&Path) -> bool + Send + Sync` (в `slam-app` — полное декодирование `decode_image` с лимитами загрузчика текстур). Без проверки поведение прежнее: решает индекс файлов. `SkinChain` хранит проверку и ставит её скинам, которые добавляются позже (`set_user`, `with_beatmap`); новая проверка сбрасывает запомненные результаты.
- **Один раз на файл.** Результат проверки запоминается в записи индекса (`OnceLock`) на время жизни загруженного скина; предупреждение `tracing::warn!` с путём и причиной пишет проверка при первой неудаче, повторно файл не декодируется и не логируется.
- **Где выполняется.** Проверка идёт в потоке, который ищет текстуры: при подготовке игры (загрузчик карты), не в update и не в draw. Декодирование для выгрузки остаётся в потоке `slam-texture-load` (ADR-0034 не меняется).
- Звуки скина не проверяются: это отдельная задача.

## Последствия
- Каждое найденное изображение скина декодируется дважды: проверкой при поиске и загрузчиком текстур. Подготовка игры дольше на время декодирования используемых элементов в потоке загрузчика карты; работа идёт параллельно с потоком `slam-texture-load`. Если замер покажет заметную задержку — передавать проверенные пиксели загрузчику через `load_pixels`.
- Скин загружается на каждую игру, поэтому предупреждение о битом файле повторяется раз в игру, а не раз за запуск.
- Файл, испорченный на диске между проверкой и чтением загрузчиком, по-прежнему даёт `TextureState::Failed`.
- Снимается расхождение с лазером из «Последствий» ADR-0058.

## Отвергнутые варианты
- Повтор по `TextureState::Failed`: результат приходит асинхронно, элемент несколько кадров пустой, а выбор провайдера и анимации к этому времени уже сделаны — нужна машина повторов в `slam-play`.
- Проверять только заголовок файла (сигнатура, IHDR): дёшево, но не ловит обрезанные данные.
- Декодировать при поиске и держать пиксели до запроса загрузчику: одно декодирование вместо двух, но все изображения скина разом в памяти — нарушается ограничение ADR-0034 на число декодированных буферов.
- Декодирование внутри `slam-skin`: новая зависимость от декодеров в библиотеке, которая по таблице ARCHITECTURE §3 зависит только от `slam-formats`.
- Проверять все изображения при загрузке скина: декодируются сотни файлов меню, которые игре не нужны.

# ADR-0104: Рендер на Windows — OpenGL по умолчанию, Direct3D 11 по выбору в настройках

- Статус: Принято, уточнён ADR-0105
- Дата: 2026-11-06
- Заменяет [ADR-0024](0024-render-backend-per-platform.md) в части Windows и уточняет [ADR-0080](0080-hlsl-and-backend-selection.md) (порядок выбора бэкенда). Закрывает вопрос [#29](https://github.com/sheynor43/SLAM/issues/29).

## Контекст
ADR-0024 выбрал D3D11 основным на Windows без замеров. Предпосылка была такой: OpenGL в окне и в borderless показывается через композитор DWM, а у D3D11 есть flip-model, tearing и waitable swapchain. ADR-0024 требовал нового ADR, если D3D11 окажется хуже OpenGL.

Замер на RX 6700 XT, Windows 11 ([2026-11-06](../perf/2026-11-06-d3d11-dense-scene.md)):
- В окне оба рендера показываются через DWM (PresentMon: D3D11 `Composed: Flip`, OpenGL `Composed: Copy with GPU GDI`), до экрана ~11 мс у обоих. D3D11 при этом ждёт на GPU освобождения back buffer и в плотной сцене даёт на 32 % меньше FPS.
- В borderless оба идут в режиме `Hardware: Independent Flip` с tearing: драйвер AMD показывает OpenGL через DXGI. Предпосылка ADR-0024 для этого драйвера не верна. В плотной сцене D3D11 медленнее по среднему FPS на ~9 %, но лучше по p99 кадра (0,41 против 0,48 мс) и по времени до экрана (0,41 против 0,53 мс).
- Загрузка буферов, вызовы и смены состояний у рендеров стоят одинаково. Разница — в пути показа DXGI.

Владелец выбрал OpenGL по умолчанию. Тот же рендер, что на Linux, проверен дольше. D3D11 остаётся выбором в настройках.

## Решение
- **Рендер по умолчанию на всех ОС — OpenGL 3.3.** `Renderer::Auto` (и `--renderer auto` у `bench` и `play`) значит «рендер платформы по умолчанию», то есть OpenGL. Отката с OpenGL на D3D11 нет.
- **Настройка** `[window] renderer`: `"opengl"` (по умолчанию) или `"d3d11"`. Поле есть в файле на всех ОС, как `video_driver` (ADR-0097); вне Windows оно игнорируется, и всегда работает OpenGL. Неизвестное значение даёт OpenGL с предупреждением в логе, как у других полей (`window.renderer: …`).
- **Выбор D3D11 в настройках** — D3D11 с откатом: если устройство или swapchain не создаются (нет `d3dcompiler_47.dll`, нет оборудования D3D11), в лог пишется причина и открывается OpenGL. Значение в настройках при этом не меняется: у osu-framework настройка сбрасывается в Automatic, но у нас откат и так происходит при каждом запуске, а сброс прятал бы выбор игрока.
- **Флаги** `--renderer opengl|d3d11|auto` у `bench` и `play` главнее настройки (они её не читают). `--renderer d3d11` — без отката, для замеров (ADR-0080).
- **Экран настроек:** строка «Рендер» в разделе экрана, рядом с видеодрайвером, **только на Windows**. Значения — «OpenGL» и «Direct3D 11», без «Авто». Применяется после перезапуска: рендер выбирается при создании окна. Строка помечается тем же маркером «после перезапуска», что и видеодрайвер (ADR-0097). Лазер в этом месте закрывает игру через диалог подтверждения; у нас маркер, без диалога.
- В лог по-прежнему пишется `render backend: …` с выбранным бэкендом.

## Последствия
- На Windows по умолчанию работает OpenGL. В borderless и fullscreen это тот же режим показа, что у D3D11, со средним FPS в плотной сцене чуть выше, но с хвостом кадра и временем до экрана чуть хуже.
- D3D11 остаётся в сборке и в CI. Его поддержка, HLSL и `d3dcompiler_47.dll` никуда не деваются: игрок может его выбрать.
- Оконный режим на Windows для минимальной задержки бесполезен у обоих рендеров: DWM показывает кадр раз в обновление экрана.
- В этой сессии OpenGL на Windows дважды из шести запусков упал при старте на `wglMakeCurrent()`. Если это повторится у игроков, по умолчанию выбран рендер с известным сбоем запуска — нужна отдельная задача.
- Замеры сделаны на одной машине (AMD). На NVIDIA и Intel картина может быть другой; если там D3D11 заметно лучше, решение можно пересмотреть новым ADR.

## Отвергнутые варианты
- **Auto = D3D11 с откатом на OpenGL (как было).** Рекомендация замера: чуть меньше задержка до экрана и лучше p99 при сравнимом FPS. Владелец выбрал OpenGL.
- **«Авто» как третье значение в настройках.** Это было бы то же самое, что OpenGL, но под другим именем; две строки с одним смыслом путают.
- **Сброс настройки в OpenGL после неудачного D3D11** (как в osu-framework). Тогда после временного сбоя (например, драйвер обновляется) игрок молча теряет свой выбор.
- **Применять рендер без перезапуска.** Рендер выбирается при создании окна, и сцены мономорфизированы по бэкенду (ADR-0080). Пересоздание окна и всех ресурсов — крупная переделка ради редкого действия.

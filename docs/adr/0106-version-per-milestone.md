# ADR-0106: Нумерация версий по этапам

- Статус: Принято
- Дата: 2026-11-07
- Уточняет [ADR-0068](0068-alpha-release-packaging.md) (пункт «Версия»).

## Контекст
ADR-0068 записал версию первой альфы — `0.0.1-alpha`. Правила, как версия растёт дальше, в нём нет. Вторая альфа вышла как `0.0.2-alpha` (патч), а этап M2 закрыт. Тестерам и самому проекту нужно видеть по номеру, до какого этапа ROADMAP дошла сборка.

## Решение
- **Minor поднимается с каждым закрытым этапом** ROADMAP, начиная с M2: закрытие M2 → `0.1.0`, M3 → `0.2.0` и т. д. Patch обнуляется.
- **Patch** — промежуточные релизы внутри этапа (исправления, сборки для тестеров): `0.1.1`, `0.1.2`…
- **Суффикс `-alpha`** у всех версий до отдельного решения о бета-версии или `1.0`.
- Версия — одна на весь workspace (`[workspace.package] version`); тег релиза — `v<версия>`, по нему `release.yml` собирает pre-release (ADR-0068).
- При закрытии этапа: поднять версию, дописать раздел «What's new» в `packaging/release-notes.md`, слить PR, поставить тег, закрыть milestone на GitHub.
- Закрытие M2 → `0.1.0-alpha`, тег `v0.1.0-alpha`.

## Последствия
- Номер версии однозначно говорит, какой этап закрыт последним.
- Цифры minor не совпадают с номером этапа (M2 → 0.1), а отстают на два; соответствие видно в release notes.
- Когда переходить к `1.0` и убирать `-alpha`, решается отдельным ADR.

## Отвергнутые варианты
- **Minor равен номеру этапа** (M2 → `0.2.0`) — нагляднее, но M0 и M1 релизов не имели, и скачок с `0.0.2` на `0.2.0` выглядел бы как пропущенная версия.
- **Только patch до релиза** (`0.0.3`, `0.0.4`…) — номер ничего не говорит о прогрессе по ROADMAP.
- **Календарная версия** (`2026.11`) — не показывает этап и плохо сочетается с semver в Cargo.

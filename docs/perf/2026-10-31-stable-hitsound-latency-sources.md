# Задержка «нажатие → хитсаунд» у stable: опубликованные замеры

- Дата: 2026-10-31
- Задача: [#264](https://github.com/sheynor43/SLAM/issues/264), решение — [ADR-0079](../adr/0079-stable-hitsound-delay-estimate.md).
- Итог: собственного замера нет. Сквозная задержка типичного stable на Windows без REAL — **около 40 мс**, оценка разности stable − SLAM — **15–25 мс**, выбрано 20 мс.

## Источники

### Форум osu!, «Keypress-to-hitsound delay» (2019)
<https://osu.ppy.sh/community/forums/topics/794196>

Запись телефоном рядом с клавиатурой или мышью и наушниками, NoFail, музыка 0 %, FPS без ограничения, 35–52 нажатия на вариант. Windows 10, встроенный Realtek ALC892.

| Клиент и вариант | Медиана | Разброс |
|---|---|---|
| stable, драйвер Realtek, клавиатура USB 125 Гц | 45 мс | 40–50 мс |
| stable, драйвер Realtek, мышь 1000 Гц | 40 мс | 37–44 мс |
| stable, Windows HD Audio, без REAL | 41 мс | 36–46 мс |
| stable, Windows HD Audio, с REAL | 26 мс | 21–31 мс |
| stable, Windows 7, драйвер Microsoft | 47 мс | 43–54 мс |
| lazer 2019.1205, без REAL | 56 мс | 50–60 мс |
| lazer 2019.1205, с REAL | 42 мс | 36–47 мс |

Второй участник (Windows 10, HD Audio) в среднем получил 40,3 мс без REAL и 31 мс с REAL. Оценка автора по частям, отдельно не измерялась: BASS 0–10 мс, антидребезг ввода около 5 мс, USB-аудио около 8 мс.

### ppy/osu #12597 (2021)
<https://github.com/ppy/osu/issues/12597>

Микрофон рядом с наушниками и мышью, Audacity, Realtek, с REAL: stable 35 мс, lazer 41 мс. Позже автор признал, что разница в пределах шума.

### keyasio.net (README)
<https://github.com/milkitic/keyasio.net>

Без методики: штатный звук stable даёт около 40 мс, с REAL около 25 мс.

### ppy/osu discussion #22917 (2023)
<https://github.com/ppy/osu/discussions/22917>

Около 60 мс и в stable, и в lazer у одного пользователя. Ответ разработчика: задержка сильно зависит от частоты update и от звукового железа.

## Оценка разности stable − SLAM
- Сквозные цифры stable включают ввод, драйвер и ЦАП конкретной машины. Их нельзя вычитать из замера SLAM на другой машине. Пример: [замер SLAM](2026-10-10-click-to-sound.md) — 25,4 мс, из них 16–23 мс приходятся на USB-интерфейс, который был бы и у stable.
- REAL укорачивает период общего режима WASAPI и снимает со stable 14–15 мс. Буфер BASS, по оценке автора форумного замера, добавляет до 10 мс. SLAM в low-latency или exclusive режиме (ADR-0027) не имеет ни того, ни другого.
- Отсюда разность порядка 15–25 мс. Выбрано 20 мс (ADR-0079).

## Не проверялось
- Ни stable, ни SLAM на одной машине с одним выходом. SLAM на Windows не замерен (#35).
- stable под Wine на Linux.

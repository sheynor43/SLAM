# Лимитер кадров: джиттер

- Дата: 2026-10-08
- Изменение: первая реализация лимитера (`slam-engine::limiter`), замера «до» нет.
- Метрика: опоздание возврата из `FrameLimiter::wait()` относительно дедлайна кадра. Бюджет (ARCHITECTURE §18): p99 < 50 мкс.

## Машина
- AMD Ryzen 7 5700X (8 ядер / 16 потоков), 16 ГБ ОЗУ
- Linux 7.2.8-1-cachyos, governor `performance`
- Рабочий стол, обычная фоновая нагрузка; приоритет потока и привязка к ядру не настраивались.

## Команда
```
cargo build -p slam-engine --release --example limiter_jitter
target/release/examples/limiter_jitter <секунд на частоту> <порог spin, мкс>
```

## Выводы
- При пороге 200 мкс бюджет p99 < 50 мкс выполняется с большим запасом на всех частотах.
- Без активного ожидания `clock_nanosleep` просыпается в среднем на ~50 мкс позже дедлайна (timer slack по умолчанию), и p99 выходит за бюджет. Порог 50 мкс почти перекрывает это опоздание, но чаще пропускает дедлайны.
- Редкие выбросы до ~0.9 мс — это вытеснение потока планировщиком. Снизить их могут приоритет и привязка потока отрисовки к ядру; это вопрос будущей задачи про потоки ([#4](https://github.com/sheynor43/SLAM/issues/4)).
- Windows пока не замерялся: код только компилируется в CI.
